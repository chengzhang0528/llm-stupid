## 目标

在当前 Windows x64 机器上由纯托管 C# 完成本地模型加载和自回归生成，优先提高 CPU 解码吞吐，并以 llama.cpp 的固定构建与相同 GGUF 作为参考。模型运行能力、服务传输和性能观测彼此可替换、可独立验证。

## 当前支持边界

- 首个验收模型为 `Granite-3.1-1B-A400M-Instruct`、Q4_K_M、GGUF v3。权重由工作区外的本地模型文件提供；仓库不存权重。
- Q4_K_M 是混合量化，首个模型所需张量类型和 Granite MoE 结构由该 GGUF 实际清单决定；不宣称支持任意 GGUF 模型。
- llama.cpp 仅是固定性能/行为参照，不进入 C# 进程、不作为 NuGet/native 依赖。
- 当前主机 CPU 为 Intel Core i5-10500，支持 AVX2；优化路径仍须有可测的标量回退。实测后默认使用最多 10 个 CPU 线程，`LLM_THREADS` 可覆盖服务线程数。

## 责任边界

- 引擎核心拥有 GGUF 元数据与张量访问、Tokenizer、模型执行、量化算子、KV cache、采样和停止条件。
- 推理图通过 `IQuantKernelBackend` 注入计算后端；当前托管 CPU 实现包含 AVX2 快路径和标量回退，替换后端不要求服务宿主了解具体核实现。
- 服务宿主拥有 HTTP/API、并发请求和取消；它只调用引擎公开接口，不持有模型计算实现。
- 性能入口拥有可复现实验参数与指标采集；服务加载、提示词处理、首 token、稳定生成、总延迟和内存分别测量，不互相推算。
- 模型格式、Tokenizer、算子执行和服务宿主通过窄接口解耦；模型专有逻辑不泄漏进通用内存/张量底层。
